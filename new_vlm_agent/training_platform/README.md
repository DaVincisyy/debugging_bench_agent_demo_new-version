# VLM Agent Training & Efficiency Platform

## Purpose
This platform turns the VLM test point localization agent into a measurable training/evaluation system. Goal:
- Keep task success rate / accuracy unchanged (match golden outputs in `tests/` and `training_platform/golden/`)
- Reduce total end-to-end time from ~5-6min to <2min
- Reduce per-LLM-call time (currently 20-35s) by optimizing prompts, image sizes, step ordering, tool inputs, etc.
- Provide structured logs + golden references so the Cursor Agent (the analyzer) can systematically diagnose bottlenecks after every run and propose targeted, recorded improvements.

## Key Directories
- `runs_archive/`: (future) archived historical run folders with timing data
- `golden/`: 完整的6个golden文件（来自tests/）：
  - case10_assembly_largest_ic_box.png
  - case10_assembly_vlm_hints.json
  - case10_largest_ic_box.png
  - case10_signal_to_tp.json
  - case10_vlm_hints.json
  - step08_result.json
- `analysis_reports/`: reports generated by Cursor Agent after each analysis session
- `proposals/`: concrete code/prompt/skill change proposals (each tied to a measured before/after)

## 全自动训练循环（真正甩手掌柜模式）

**用户只需一步：**

```powershell
# 连续跑 10 轮，每轮 = 运行 agent → 自动分析（容差 10px） → Cursor Agent 必要时直接改代码
python training_platform/train_loop.py --rounds 10
```

**完整闭环逻辑：**
1. 第 N 轮运行 agent（使用当前代码/技能）
2. 自动执行 `auto_analyze.py`（像素容差已收紧为 **10px**）
3. 生成 `analysis_reports/<run_id>.json` + 更新 `accuracy_trend.json`
4. **如果需要优化**（或总是尝试找提速点），**Cursor Agent 直接修改代码**，并在被改文件顶部 + `EFFICIENCY_LOG.md` 记录改动
5. 第 N+1 轮自动使用修改后的版本运行
6. 10 轮结束后，查看 `train_loop_log.jsonl` 即可看到每轮的时间、准确性、改动历史

**容差与告警策略（已按你的要求调整）：**
- 像素容差：**10px**（|dx| 和 |dy| 都 ≤ 10 才算通过，比之前严格很多）
- 连续失败阈值：2（连续 2 次超出 10px 才写入 `needs_attention.json`）
- 单次失败只记录，连续失败才触发重点分析

**优点**：
- 你完全不用管，跑完 `train_loop.py` 就能看到 10 轮的迭代效果
- 每次改动都会被下一轮直接验证（验收收益）
- 如果改坏了，连续失败会自动暴露，Cursor Agent 下次分析时会回滚或调整

**注意**：`train_loop.py` 内部会调用 `python -m agent`，请确保环境变量和依赖正确。

---

### 准确性判断策略（带容差 + 多次失败才告警）

- **像素容差**：`step08_result.json` 中的坐标允许 ±40 像素偏差（可配置）。只要 |dx| 和 |dy| 都 ≤ 40px，就认为“准确性可接受”。
- **多次失败才注意**：单次超出容差会记录但不告警；连续 ≥2 次（可配置）超出容差，才写入 `needs_attention.json`，触发 Cursor Agent 深度分析。
- **优点**：允许流程在优化前期偶尔不稳，避免过早修改；真正的问题会通过“连续失败”暴露出来。

## Recording Rule (Mandatory)
Every modification (skill, prompt, tool input, image prep, etc.) MUST be recorded in at least one of:
- A `## Efficiency Change Log` section at the top of the modified source file
- The central `training_platform/EFFICIENCY_LOG.md`
- A dedicated file in `proposals/`

The record must include: date, before/after timing (if measured), accuracy impact (golden match?), rationale, and which run ID it was validated on.
